# 录播整理文档更新脚本 · 使用文档

脚本文件：`update_reaction_doc.py`

作用：读取项目数据库（`bili-clip-flow.sqlite3`）里的 B站投稿任务 + 百度网盘路径，把「上次更新之后新建的投稿」按现有《主播-分类》结构增量追加进 `录播整理2.xlsx`，供你上传到腾讯文档。

## 一分钟上手

```bash
# 日常：把库里新出现的投稿追加进文档（新增行会标黄供你核对）
python3 update_reaction_doc.py

# 核对无误后：清除黄色标记
python3 update_reaction_doc.py --confirm
```

然后把 `录播整理2.xlsx` 重新上传到腾讯文档即可。

## 安装依赖

- **Python 3**（macOS 自带；没有就装官方版或 Xcode 命令行工具）
- **openpyxl**（唯一需要额外安装的库，用于读写 xlsx）：
  ```bash
  pip3 install openpyxl
  ```
- 数据库读取用 Python 自带的 `sqlite3`，无需安装。

> 缺 openpyxl 时脚本会直接提示你安装命令。

## 命令一览

| 命令 | 作用 |
|---|---|
| `python3 update_reaction_doc.py` | 增量更新；新增行标黄；写入前自动备份 |
| `python3 update_reaction_doc.py --dry-run` | 只预览会加多少、加到哪，**不写文件** |
| `python3 update_reaction_doc.py --confirm` | 确认完成：清除全部黄色标记（不新增任务） |
| `python3 update_reaction_doc.py --init` | 文档不存在时新建空白并**从库全量生成** |
| `python3 update_reaction_doc.py <db路径> <xlsx路径>` | 自定义数据库/文档路径 |
| `python3 update_reaction_doc.py --help` | 查看帮助 |

参数可组合，例如：`python3 update_reaction_doc.py "/新db" "/新xlsx" --dry-run`

**默认路径**（不传参时）：
- 数据库：`~/Library/Application Support/com.tbw.biliclipflow/bili-clip-flow.sqlite3`（找不到会自动发现）
- 文档：`~/Downloads/录播整理2.xlsx`

## 它是怎么工作的

### 1）增量靠「时间水位」
- 文档里有一张 **《更新记录》** 表，记录每次运行的「水位」= 运行时库中投稿任务的**最新创建时间**（格式 `yyyy-MM-dd HH:mm:ss`）。
- 每次运行读取上次水位，只查询 `created_at >= 上次水位` 的任务（重扫水位那一秒，避免同秒漏加），再靠 **BV 去重** 防重复；跑完把水位推进到最新，并在《更新记录》追加一行。
- 首次运行（还没有《更新记录》）：扫描全部 → BV 去重后一般 0 新增 → 写入基线水位。

### 2）文档就是「分类记忆」（自描述）
脚本决定一个视频进哪张表，按优先级：
1. **该作品已在文档里出现** → 沿用它所在的分类表；
2. 否则 **看网盘路径里的分类目录**（见下）→ 自动归类；
3. 都没有 → 放进 `主播-未分类`，等你手动归（归好后下次自动沿用）。

> 换句话说：**你只增不删，分类记忆就一直在，新集永远进对表**。

### 3）同名并组 / 排序 / 合并单元格
- 视频名称取网盘路径的**末级文件夹**（`Season1/剧场版/part` 等通用目录会自动上取一级作品名）。
- 同一作品的多集会**并入同一组**、按集数**自然排序**、并把「视频名称」列**合并单元格**（与你之前手工整理的样式一致）。

## 分类规则

网盘路径里的目录名 → 分类（大小写不敏感）：

| 路径目录 | 归类 |
|---|---|
| `anime` / `动漫` / `动画` / `番剧` | 番剧 |
| `movie` / `电影` | 电影 |
| `电视剧` / `影视` / `tv` / `剧集` | 电视剧 |
| `特摄` / `tokusatsu` | 特摄 |
| 以上都没有 | 未分类（待人工归） |

分类表排列顺序固定为：**番剧 → 电影 → 电视剧 → 特摄 → 未分类**。

> 有些主播（如七海）的网盘不带分类目录，作品直接放在主播名下 → 这些会进「未分类」，需要你手动归一次。

---

## 黄色「待确认」机制

- 每次更新**新增的视频行**会被填成**黄色**，供你核对。
- 黄色**跨多次运行保留**：在你确认之前，反复运行脚本，黄色一直都在（重建时自动重新上色）。
- 核对无误后，运行 `--confirm` **清除全部黄色**（只去色、不动任何数据、不推进水位、不写更新记录）。
- 你在腾讯文档/Excel 里**手动改的黄色**也会被 `--confirm` 一并清除。

## 从零生成 / 换电脑

### 换一台 Mac
基本**零配置**：只要 app 装在标准位置、跑过一次生成了数据库，脚本会自动发现库；文档默认在 `~/Downloads/录播整理2.xlsx`。缺库时会自动搜索（见下）。

### 数据库自动发现
不传库路径、且默认路径不存在时，脚本按顺序找：
1. 各系统标准子路径（macOS `~/Library/Application Support/com.tbw.biliclipflow/`、Windows `%APPDATA%`/`%LOCALAPPDATA%`）；
2. 候选目录下递归搜 `bili-clip-flow.sqlite3`；
3. 兜底：搜任意含 `submission_task` 表的 `.sqlite3/.db`。
找到会打印 `🔎 自动发现数据库: …`；实在找不到才报错、让你手动传路径。

### 从零生成整个文档
```bash
python3 update_reaction_doc.py --init     # 新建空白 → 从库全量生成(全部标黄)
#   把“未分类”里的作品手动归到正确分类
python3 update_reaction_doc.py --confirm  # 清除黄色
```
> 注意：从零生成时，**无分类目录的作品（约 1/4）会全部进「未分类」**，需要你手动归一次；已归好后以后自动沿用。
> 不加 `--init` 时，文件不存在会直接报错（防误操作）。

### 跨系统（Windows/Linux）
- 纯 Python，Windows 可直接 `python update_reaction_doc.py`，无需 bash。
- 但库/文档路径不同，需用参数传入：`python update_reaction_doc.py "<db>" "<xlsx>"`。

## 可配置项（改脚本）

打开 `update_reaction_doc.py`，顶部「可调配置」区可改：

| 变量 | 含义 |
|---|---|
| `ACC` | B站账号 uid → 显示名映射。**新账号需在此加一行**，否则「对应账号」列显示原始数字 |
| `SKIP_BVS` | 永不再加入的 BV（已人工删除的）。要永久排除某投稿，把它的 BV 加进来 |
| `PATHCAT` | 路径目录 → 分类 的对应表，可扩充新目录词 |
| `CATORDER` | 分类（=sheet）排列顺序 |

`main()` 里的 `default_db` / `default_xlsx` 是默认路径，换机固定路径可直接改这两行。

## 常见问题 FAQ

**Q：新增了一个新主播的视频，会自动建表分类吗？**
会。脚本从路径提取主播名，自动新建 `新主播-番剧 / -电影 / …` 等表；能不能分对，取决于该主播路径里有没有分类目录，没有的进「未分类」待手动归。新账号需在 `ACC` 里补映射。

**Q：脚本能直接改线上腾讯文档吗？**
不能。它只改本地 xlsx，你需要手动把 xlsx 重新上传/导入腾讯文档。

**Q：会不会重复添加、或改动我已有的行？**
不会。只追加「BV 还不在文档里」的新任务；已有行/合并/顺序一律不动。（可先用 `--dry-run` 预览。）

**Q：多次运行安全吗？**
安全（幂等）。没有新任务时重跑不产生任何改动。

**Q：某个投稿没有网盘路径，会怎样？**
跳过（`跳过(无网盘路径)` 计数），因为无法填「网盘路径」列。

## 边界与限制（务必了解）

1. **只增不删、不改已有行**。脚本不做删除、不改分类；这些是人工操作。删除某投稿请把它的 BV 加进 `SKIP_BVS`，并手动删掉文档里的行。

2. **1 个任务 = 1 行**。脚本按库里每个任务的 `网盘路径 + 文件名` 生成 1 行。若你在文档里把某个任务**手工拆成多个网盘文件行**，脚本不会重生成那种粒度，但也**绝不删除**你手工加的行。

3. **无分类目录的作品进「未分类」**。这类作品的分类只能靠你手动归一次；归好后脚本会记住（自描述），以后同作品的新集自动进对表。**前提是别把该作品从文档里整组删光**——一旦删光，这份「分类记忆」就没了，下次只能按路径猜或进未分类。

4. **文件必须存在**（除非用 `--init`）。文档不存在且没加 `--init` 会报错，脚本不会凭空建文件。

5. **需要 xlsx 是「多 sheet + 合并单元格」结构**，所以依赖 openpyxl；不能换成 CSV。
